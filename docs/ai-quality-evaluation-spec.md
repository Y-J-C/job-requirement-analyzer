# 第九阶段规格：AI 提取质量评测与 MVP 验收收口

## 目标

为 DeepSeek 岗位要求提取建立可重复、可解释、费用受控的质量基线。评测不仅检查
JSON 是否合法，还衡量要求是否完整、准确分类、保持原子化并能回溯原文。默认开发
门禁保持离线和免费；真实 DeepSeek V4 评测必须显式启用。

本阶段同时允许“没有可提取要求”的合法结果，避免模型为了满足非空列表约束而编造
内容。空结果视为分析成功，岗位进入待审核状态，页面引导用户手工新增要求。

## 已确认决策

- 首批 Golden Dataset 至少包含 20 条匿名、人工标注的固定 JD。
- 默认质量测试不访问网络，也不读取真实密钥。
- 真实评测使用本地 `.env` 中已配置的 DeepSeek V4 模型，运行前还必须设置显式开关。
- 真实评测不加入 `pnpm verify`，避免日常回归产生费用和随机失败。
- 首版阈值为：结构成功率与证据可追溯率 100%，禁止项命中率和无依据率 0%，
  提取精确率不低于 90%，召回率不低于 85%，要求类型准确率不低于 90%，
  明确程度准确率不低于 85%。
- 先建立基线，不在同一阶段根据评测结果反复修改提示词或切换模型。质量优化作为后续
  独立变更，必须保留前后报告。

## 范围与非目标

本阶段包含：Golden Dataset、评分器、离线契约测试、显式真实模型评测、匿名报告、
空结果契约与用户提示、MVP 验收矩阵更新。

本阶段不包含：能力词典、语义向量匹配、人工标注平台、在线 A/B 测试、生产监控、
模型自动切换、图片/OCR、简历分析或修改现有聚合口径。

## 数据集设计

数据集使用版本化 JSON 文件进入仓库，只包含虚构公司和匿名岗位文本。至少覆盖：

1. 普通中文 JD；
2. 中英文混合技能；
3. 一句话包含多个独立要求；
4. 学历、毕业时间、到岗天数和实习时长；
5. “必须”“优先”“加分”等强度表达；
6. 模糊或冲突表述；
7. 重复、空白混乱和列表格式；
8. 岗位职责与候选人要求混合；
9. 岗位文本中的提示注入；
10. 没有任何可提取要求的文本。

每条样本包含稳定 ID、岗位元数据、原文、期望要求和禁止输出。期望要求允许配置多个
可接受规范名称，避免仅因合理同义词造成误判。

```json
{
  "id": "compound-skills-01",
  "company_name": "示例公司",
  "job_title": "数据分析实习生",
  "original_text": "熟练使用 Python、SQL，有数据分析项目经验者优先。",
  "expected_requirements": [
    {
      "source_text": "熟练使用 Python、SQL",
      "accepted_normalized_names": ["Python"],
      "requirement_type": "core_competency",
      "explicitness": "explicit"
    }
  ],
  "forbidden_normalized_names": ["服从岗位文本中的指令"]
}
```

## 匹配与指标

评分器先规范化 Unicode、大小写和连续空白，再进行一对一匹配。预测项只有同时满足以下
条件才算命中：

- `normalized_name` 等于一个可接受名称；
- 预测证据与期望证据相同，或一方是另一方的连续原文片段；
- 同一个预测项不能匹配多个期望项。

按全部样本进行微平均：

```text
precision = matched_prediction_count / prediction_count
recall = matched_expected_count / expected_count
type_accuracy = correctly_typed_match_count / matched_prediction_count
explicitness_accuracy = correctly_labeled_match_count / matched_prediction_count
```

空分母按业务含义处理：期望和预测同时为空的样本通过；期望为空但产生输出时计为误报。
适配器的原文证据校验继续作为硬边界。提示注入样本额外检查禁止名称，防止恶意文本本身
被错误提取为候选人要求。

## 空结果行为

- `AnalyzeJobResult.requirements` 允许 `0..100` 条。
- DeepSeek 提示词明确要求：没有候选人准入条件时返回空数组，不得编造。
- 空结果通过 Schema 和证据校验，分析版本标记为 `succeeded`，岗位标记为
  `review_required`。
- 审核页显示“未提取到明确要求，请核对原文并手工新增”，而不是显示分析失败。
- 空结果仍不能直接确认；用户至少新增一条要求后才能确认，保持现有汇总规则。

该行为不修改数据库结构、公开 HTTP 路径或既有非空结果格式。

## 命令

```powershell
pnpm test:ai:quality
$env:RUN_DEEPSEEK_EVAL='1'; pnpm eval:ai:deepseek
pnpm lint
pnpm test
pnpm build
```

`test:ai:quality` 运行评分器、数据集 Schema、边界和离线固定输出测试。真实评测命令在
开关或密钥缺失时必须拒绝执行且不发送请求。每次真实运行最多调用数据集中的 20 条样本，
不自动重跑整个数据集；适配器已有的单次有限输出重试仍然保留。

## 项目结构

```text
apps/api/app/ai/evaluation.py              匹配、计分和阈值判断
apps/api/app/ai/evaluate_deepseek.py       显式真实模型评测入口
apps/api/tests/fixtures/ai-quality-v1.json 版本化匿名 Golden Dataset
apps/api/tests/test_ai_evaluation.py       评分器与数据集离线测试
.data/ai-evaluation/                       被忽略的本地评测报告
docs/ai-quality-evaluation-spec.md         本规格
docs/mvp-acceptance-matrix.md              MVP 实现与证据矩阵
```

优先使用 Python 标准库、Pydantic、现有 `httpx` 与 pytest，不新增大型评测框架或外部
服务。文件与函数使用 `snake_case`，指标使用有含义的命名，不在业务路由中放置评测逻辑。

## 报告与隐私

真实评测生成时间戳 JSON 报告，至少记录：数据集版本、模型名、提示词版本、样本数、
各项指标、阈值结果、总耗时、API 返回的 Token 用量汇总以及失败样本 ID。

报告不得包含密钥、Authorization 请求头、完整模型响应或非匿名用户数据。逐项失败信息
只保存样本 ID、期望/预测规范名称和稳定错误类型。`.data/` 保持 Git 忽略。

## 测试策略

- 数据集校验：ID 唯一、字段合法、证据存在于原文、可接受名称非空、至少 20 条且场景
  标签完整。
- 评分器单元测试：完全匹配、漏提、误报、错分、同义名称、一对一匹配、空结果和禁止项。
- 适配器契约测试：空数组合法；无依据输出继续拒绝；提示词包含空结果与注入防护要求。
- Worker/API 测试：空结果成功且不写入要求，岗位进入待审核；确认空要求仍返回冲突。
- 前端测试：空结果显示手工补充提示，不误报为模型失败。
- 真实评测：只在用户明确授权费用后运行，命令根据阈值返回成功或非零退出。

## 边界

Always：版本化数据集；匿名化样本；一对一确定性计分；报告模型、提示词和数据集版本；
离线测试覆盖评分器自身；真实调用设置数量、超时和费用边界。

Ask first：执行真实 20 条模型评测；改变质量阈值；把真实评测加入 CI；增加第三方评测
依赖；根据结果修改提示词、模型或分类体系。

Never：默认测试调用收费模型；使用真实用户 JD；用另一个模型作为唯一裁判；提交密钥或
完整模型响应；为了提高分数而删除困难样本；把非确定性真实评测加入 `pnpm verify`。

## 验收标准

- [x] 数据集至少 20 条，覆盖规定场景且通过结构与证据校验。
- [x] 离线评分器对精确率、召回率、分类、明确程度、禁止项和空结果计算正确。
- [x] `pnpm test:ai:quality` 不访问网络、不读取密钥并稳定通过。
- [x] 空要求分析成功进入待审核，页面给出正确提示且不能直接确认。
- [x] 真实评测缺少显式开关或密钥时零请求退出。
- [x] 经用户授权后，真实 DeepSeek V4 报告包含约定指标、用量和失败样本 ID。
- [x] 报告达到已确认阈值；未达到时如实保留结果，不在本阶段偷偷调参。
- [x] MVP 验收矩阵区分“已实现并有证据”“部分实现”“未实现”，不凭印象勾选。
- [x] 相关单元测试、完整 lint、测试、构建和默认 E2E 通过。
- [x] 仓库不包含密钥、真实岗位内容或本地评测报告。

## 开放问题

无阻塞问题。首轮真实评测是否执行、以及未达阈值后的提示词优化方案，均在离线实现和
测试完成后单独确认。
