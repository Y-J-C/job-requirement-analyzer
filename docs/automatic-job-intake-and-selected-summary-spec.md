# 岗位自动录入与选定岗位综合分析规格

## 目标

面向本地单用户，建立一条无需重复操作的岗位录入主流程：用户以文字、文档或图片提交一个
岗位后，系统自动提取原文、识别公司与岗位名称、执行一次 AI 指标分析，并把每项指标及其
原文依据持久化。岗位列表展示全部记录，用户可勾选任意已确认岗位或全选，再只针对选中
集合计算综合结果。

系统自动分析不等于自动采信。公司和岗位名称允许修改；AI 指标必须经人工审核确认后，
才能进入正式综合分析。识别失败时显示“待补充”，不得编造元数据。

## 已确认的产品决策

- 提交后自动进入解析/OCR 和 AI 分析，不再要求用户点击“开始分析”。异步处理期间显示
  `解析中`、`识别中`、`分析中`、`待审核`、`已确认`或`失败`。
- 公司名称、岗位名称和城市由 AI 从原文识别，允许用户修改；来源 URL 仅保存用户输入。
- 文字、文档和图片是互斥的三种来源，一次提交只创建一个岗位。
- 文档一次上传一个，支持 PDF、Markdown、DOCX。
- 图片一次上传 1～10 张，支持 PNG、JPEG、WebP；按用户选择顺序 OCR、拼接和分析，
  仍只创建一个岗位、一次 AI 分析运行。
- 综合分析只使用已人工确认的指标。未完成审核、失败或元数据仍缺失的岗位继续显示在
  列表中，但不可被选入正式综合分析。
- 选择状态是页面临时状态，不写入数据库；刷新页面后可重选。综合结果不创建新的持久化
  分析记录，始终由已确认指标确定性计算。

## 用户流程与验收行为

### 1. 自动录入

1. 用户选择目标岗位方向，并选择“粘贴文字”“上传文档”或“上传图片”。
2. 用户提交一次；招聘阶段默认继承目标方向，城市、来源 URL 可选。
3. 文字直接进入 AI 队列；文档完成文本解析后自动进入 AI 队列；图片全部 OCR 成功并按序
   合并后自动进入 AI 队列。
4. 同一次 AI 调用返回公司名称、岗位名称、城市候选值和原子化指标列表。
5. Worker 在一次事务中保存有效元数据和全部指标；失败时不保存半成品指标，并保留可重试
   状态与稳定错误码。
6. 用户打开岗位审核页，可修改元数据及逐项修改、新增、删除指标。公司名称和岗位名称为
   空时不能完成整份确认。

每项指标继续保存：规范名称、类型、明确程度、置信度、逐字原文证据、分析运行版本和人工
确认状态。AI 证据必须可在合并后的岗位原文中追溯。

### 2. 岗位选择和综合分析

- 岗位列表展示公司、岗位名称、来源类型、处理状态、指标数量和更新时间。
- 每个可汇总岗位有复选框；未确认岗位的复选框禁用并说明原因。
- “全选”选择当前方向下所有可汇总岗位，“取消全选”清空选择；逐项取消后只分析剩余项。
- 至少选择 2 个、最多选择 500 个岗位才能点击“综合分析”。重复 ID 被拒绝。
- 后端验证所有 ID 存在、属于当前方向且状态为已确认；任一不合法时返回明确错误，不静默
  忽略，防止页面显示的样本数与实际分母不同。
- 覆盖率分母是本次选中的已确认岗位数，不是该方向的全部岗位数。结果保留每项指标覆盖
  岗位数、覆盖率、类型、证据和回溯链接。

## API 与数据契约

新增统一录入入口：

```http
POST /api/v1/target-roles/{role_id}/jobs/intake
Content-Type: multipart/form-data
```

字段为 `source_kind=text|document|images`、可选 `original_text`、`files`、
`company_name`、`job_title`、`recruitment_stage`、`city`、`source_url`。公司和岗位字段只是
可选人工提示，非空值优先于 AI 结果。服务端严格验证三种来源只能出现一种：文字非空；
文档恰好一个；图片 1～10 张且不能混入文档。返回岗位、源文件列表和已排队状态。

新增元数据修改入口：

```http
PATCH /api/v1/jobs/{job_id}
```

只允许修改公司名称、岗位名称、城市、招聘阶段和来源 URL，不覆盖原文或分析结果。

新增选定集合汇总入口，保留现有全部确认岗位的 `GET summary` 以兼容已有调用：

```http
POST /api/v1/target-roles/{role_id}/summary
Content-Type: application/json

{"job_ids":["uuid-1","uuid-3"]}
```

响应增加 `selected_job_count` 和 `selected_job_ids`，其余指标结构保持兼容。

数据库迁移应：将 `company_name`、`job_title` 调整为处理期间可空；把 `SourceFile` 从岗位
一对一改为一对多；增加同岗位内唯一的 `sequence_index`。现有单文件记录迁移为顺序 0，
不得丢失已有岗位、文件或分析结果。

## OCR 与 AI 边界

DeepSeek 官方文档当前明确列出 Chat Completions、JSON Output 与 V4 Flash/Pro，但未给出可
依赖的图片输入契约。因此图片先由可替换的本地 OCR 适配器转成文本，再复用同一岗位分析
契约；不得把未记录的视觉能力当作既有 API 使用。

OCR 实现必须：离线运行；限制像素、文件大小和图片数量；自动纠正 EXIF 方向；按文件顺序
输出带分隔标记的文本；不把图片内指令当系统指令。具体 OCR 依赖在实施计划中通过中文
识别效果、Windows/Docker 可安装性、包体积、许可证和维护状态评估后确定，新增依赖随计划
一起批准。

AI 输出契约升级为新的版本，同时返回可空元数据和 `requirements`。用户手工提供的非空
元数据优先于模型候选值；模型不得凭常识补全缺失公司或岗位名称。一次岗位提交只创建一次
初始分析运行；模型非法输出可沿用现有单次有限重试，不算用户重复操作。

## 项目结构与代码风格

```text
apps/api/app/parsing/            图片验证、OCR 协议和实现
apps/api/app/services/           统一录入流水线、元数据更新、选定集合汇总
apps/api/app/api/v1/             intake、PATCH 和 summary 路由
apps/api/app/models/             JobPosting、SourceFile 兼容迁移
apps/api/app/ai/                 元数据加指标的结构化提取契约
apps/api/tests/                  单元、API 与 Worker 回归测试
apps/web/src/features/job-postings/  三种录入、状态和岗位选择
apps/web/src/features/summary/       选定集合综合结果
e2e/tests/                       自动录入与选择第 1/3 个岗位主流程
```

TypeScript 使用两空格、`PascalCase` 组件和 `camelCase` 变量；Python 使用四空格、
`snake_case` 和 100 字符行宽。新增状态转换集中在服务层，不在路由或 React 组件中复制业务
规则。OCR 与 AI 均通过协议注入，测试不得访问真实外部服务。

## 测试策略

- pytest：来源互斥、图片数量/签名/像素限制、OCR 顺序、局部失败不产生分析、自动排队、
  元数据缺失、一次分析运行、文件删除生命周期和迁移兼容。
- pytest：选中第 1/3 个岗位、全选、重复 ID、跨方向 ID、未确认岗位、覆盖率分母和证据
  回溯；证明未选岗位不会影响结果。
- Vitest/Testing Library：三种录入方式、1～10 张图片顺序、状态轮询、待补充元数据、
  复选框、全选/取消、禁用原因和提交选中 ID。
- Playwright：文字自动分析主流程、图片 OCR 主流程，以及记录三个岗位后仅选择第一个和
  第三个进行综合分析。
- 所有默认测试使用假 OCR 和假 Analyzer。真实 DeepSeek 测试继续受显式开关保护，OCR
  准确率使用固定匿名图片样本独立验证。

## 边界

Always：保留原始文字/文件；验证文件头而非只看扩展名；失败可诊断；一个岗位的初始流水线
只产生一个分析运行；综合结果严格使用所选已确认岗位；保留现有数据和 API 兼容性。

Ask first：选择并增加 OCR 依赖；改变 10 张图片、10 MiB 单文件或 500 岗位限制；改变人工
确认门槛；运行收费服务；修改既有分析质量阈值；执行生产迁移。

Never：图片内容直接作为系统指令；识别失败时编造公司或岗位；静默忽略不合法的选中岗位；
把未确认指标写入正式综合结果；提交上传文件、OCR 原文、密钥或真实岗位数据。

## 成功标准

- [ ] 三种来源均可一次提交并自动完成解析/OCR、一次 AI 分析和逐项保存。
- [ ] 1～10 张图片按选择顺序合并，同一岗位不会被拆成多个记录或多次初始分析。
- [ ] 公司和岗位名称自动识别、可修改；无法识别时明确待补充且不可整份确认。
- [ ] 页面列出全部岗位并准确显示处理状态，失败可重试且不产生半成品指标。
- [ ] 可逐项选择、全选和取消全选；未确认岗位不可选且原因可见。
- [ ] 只对选中岗位汇总，覆盖率分母、证据和选中数量完全一致。
- [ ] 旧岗位、旧单文件记录和现有全部确认岗位汇总接口继续可用。
- [ ] 单元、集成、构建和 E2E 门禁通过，默认验证不产生 DeepSeek 调用或费用。
