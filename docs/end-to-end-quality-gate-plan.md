# 第八阶段实施计划：自动化端到端测试与质量门禁

## 概览

本计划实现已批准的 `docs/end-to-end-quality-gate-spec.md`。按“运行基础 → 数据生命周期 → 确定性业务流 → 失败场景 → 可选真实模型 → 统一门禁”的依赖顺序交付。每个任务保持可独立验证；经用户确认，为补齐清理生命周期增加目标方向删除 API，不修改数据库结构。

## 架构决策

- Playwright 只运行 Chromium；`playwright.config.ts` 负责 Web、API、Worker 生命周期，PowerShell 脚本负责 Docker 与迁移前置检查。
- 浏览器断言验证用户行为；创建辅助数据、状态轮询和清理可使用公开 API，以减少慢且脆弱的 UI 操作。
- 每次运行生成唯一 ID，清理器只删除带本次唯一前缀的资源，不按宽泛条件删除已有数据。
- 默认闭环使用手工要求，真实 DeepSeek 用例单独标记并显式启用。

## 任务列表

### 任务 1：建立 Playwright 运行基础

**说明：** 安装并锁定 Playwright，配置 Chromium、失败产物、基础 URL、服务启动和 PowerShell 前置脚本。

**验收条件：**

- `pnpm test:e2e` 能检查 Docker、启动 PostgreSQL/MinIO、执行迁移并启动三个应用进程。
- 服务未就绪或 Chromium 未安装时返回非零退出及可操作提示。
- 成功用例不保留截图、视频或 Trace；失败用例保留截图和 Trace。

**验证：** `pnpm exec playwright install chromium`；运行最小 Playwright 冒烟并确认三个服务就绪。

**依赖：** 无。

**预计文件：** `package.json`、`pnpm-lock.yaml`、`playwright.config.ts`、`scripts/test-e2e.ps1`、`e2e/.gitkeep`。

**规模：** 中。

### 任务 2：建立隔离数据与兜底清理

**说明：** 创建运行上下文、公开 API 客户端和全局清理器，通过本次唯一前缀准确识别创建的资源。

**验收条件：**

- 公司、岗位和目标方向名称均带唯一 `[E2E:<run-id>]` 标识。
- 清理顺序为岗位及文件 → 目标方向，并对已不存在资源保持幂等。
- 用例失败或进程收到正常终止时仍执行 teardown；清理失败明确报告。

**验证：** 冒烟用例创建并删除临时目标方向；API 查询确认资源消失。

**依赖：** 任务 1。

**预计文件：** `e2e/support/api.ts`、`e2e/global-teardown.ts`、`e2e/tests/infrastructure.spec.ts`、`playwright.config.ts`、目标方向 API 与服务测试。

**规模：** 中。

### 任务 3：覆盖文本录入、审核与汇总主流程

**说明：** 用浏览器创建目标方向和文本岗位，通过审核页新增、编辑、确认要求，再验证汇总和原文回溯。

**验收条件：**

- 流程使用语义化角色/标签定位，不依赖 CSS 层级或元素索引。
- 确认前的要求不进入汇总；确认后覆盖率和证据正确出现。
- 测试末尾删除全部创建数据。

**验证：** `pnpm test:e2e --grep "文本主流程"`。

**依赖：** 任务 2。

**预计文件：** `e2e/tests/text-review-summary.spec.ts`；仅在缺少可访问名称时最小修改对应前端组件及测试。

**规模：** 中。

### 任务 4：覆盖 Markdown 上传与异步解析

**说明：** 上传匿名 Markdown 固定样本，观察持久化解析状态，核对原文，并验证删除生命周期。

**验收条件：**

- 浏览器实际上传文件并观察 `extracting` 最终进入 `draft`。
- 提取文本可在页面查看，随后可以建立要求、确认并进入汇总。
- 删除岗位后源文件接口返回不存在，MinIO 集成检查无遗留对象。

**验证：** `pnpm test:e2e --grep "文件主流程"`；`pnpm test:api:integration`。

**依赖：** 任务 2。

**预计文件：** `e2e/fixtures/job-posting.md`、`e2e/tests/file-upload.spec.ts`、必要的 E2E 支持模块。

**规模：** 中。

### 任务 5：覆盖安全拒绝与可恢复错误

**说明：** 验证不支持格式、超限上传以及浏览器请求失败时的用户反馈与无副作用行为。

**验收条件：**

- 不支持格式和运行时生成的超限文件显示稳定中文提示，不创建岗位。
- 网络请求失败显示可恢复错误，不泄露堆栈或内部服务信息。
- 测试不提交大型二进制夹具，临时文件在结束时删除。

**验证：** `pnpm test:e2e --grep "错误处理"`。

**依赖：** 任务 2。

**预计文件：** `e2e/tests/upload-errors.spec.ts`、`e2e/tests/network-errors.spec.ts`、必要的临时文件辅助模块。

**规模：** 中。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| Windows 子进程未退出 | 后续运行端口冲突 | Playwright 管理服务，脚本使用 `try/finally` 并验证端口 |
| Worker 状态存在竞态 | 偶发失败 | 轮询业务状态并设置明确上限，不使用固定睡眠 |
| 清理误删已有数据 | 数据损失 | 只清理本次记录的 UUID，并校验唯一运行前缀 |
| DeepSeek 波动或产生费用 | 不稳定、费用不可控 | 默认跳过，仅一个短样本且显式开关 |
| UI 文案变化导致脆弱定位 | 维护成本 | 优先角色、标签和稳定可访问名称 |
