# 岗位工作台界面优化规格

## 目标

在不改变 API、数据结构和业务规则的前提下，把首页、岗位方向页、审核页和汇总页整理为一致、紧凑、可快速扫读的工作台。优先解决标题过大、录入区挤占首屏、操作层级不清和移动端滚动过长的问题。

## 范围

- 首页：明确“创建方向 → 录入岗位 → 审核指标 → 综合分析”流程；弱化开发入口。
- 岗位方向页：桌面端采用录入侧栏与岗位记录主区；突出可汇总状态、选择数量和主操作。
- 审核页：压缩页头与元数据区，强化原文、AI 提取、人工确认三者关系。
- 汇总页：让样本量、筛选器、覆盖率和证据更易比较。
- 全局：统一排版、间距、状态色、焦点态、空状态和 390px 移动端布局；补齐站点图标。

## 约束与边界

- 保留现有中文文案含义、表单字段、链接路径和无障碍标签。
- 不新增网络字体、前端依赖、后端接口或数据库迁移。
- 危险操作仍需确认；加载、失败、禁用和处理中状态必须清晰可见。
- 开发入口保留，但移入低优先级页脚区域。

## 验收标准

- 1024px 首屏可同时看到岗位方向信息、录入入口和岗位记录起始区域。
- 390px 页面无横向滚动，表单与工具栏可完整操作。
- 所有现有 Vitest 行为测试通过；ESLint、Next.js 构建和关键 Playwright 流程通过。
- 浏览器控制台无应用资源 404；键盘焦点清晰，颜色不作为唯一状态提示。
