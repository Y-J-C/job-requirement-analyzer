# 开源发布前收尾实施计划

## 1. 实施概览

本阶段先冻结业务范围，对当前尚未提交的大批改动执行发布前审查，再补齐开源元数据、文档和 GitHub Actions，最后运行完整验证。所有修复均以发布阻塞问题为限，不借机增加业务功能或重构架构。

## 2. 关键决策

### 2.1 许可证

采用 Apache License 2.0，根目录保存标准、未经改写的许可证全文。项目文档只说明适用许可证，不自行解释法律效果。

### 2.2 CI 平台拆分

- `windows-latest`：安装 Node.js 24、pnpm 11、Python 3.12，创建项目现有 `.venv`，执行 API 契约检查、Lint、类型检查、单元测试和生产构建。
- `ubuntu-latest`：使用 GitHub 托管 Runner 自带的 Docker，启动 PostgreSQL、MinIO 和 ClamAV，执行 Alembic 迁移及基础设施集成测试。
- CI 不配置 `DEEPSEEK_API_KEY`，不执行真实模型评测或真实模型 E2E。
- 浏览器 E2E 保留在本地 `pnpm verify` 门禁；若后续需要纳入 CI，应先把 Windows 专用编排脚本标准化为跨平台脚本，单独立项。

### 2.3 文档职责

- `README.md` 作为用户安装、运行、验证和产品状态的唯一入口。
- `README-岗位门槛分析系统.md` 保留为最初产品基线，但修正已定事项和与当前架构冲突的陈述，避免新贡献者误读。
- `CONTRIBUTING.md` 只记录贡献流程和工程约定，不复制完整 README。
- `SECURITY.md` 说明漏洞报告方式、无内置认证的部署边界和密钥处理要求。

### 2.4 审查与修复边界

先审查当前工作树，再添加发布文件。发现阻塞级或高优先级缺陷时，以独立、小范围补丁修复并补回归测试；中低优先级问题只记录，不扩大本阶段范围。不会清理或覆盖无法确认来源的用户改动。

## 3. 执行顺序

```text
仓库与敏感信息审计
        ↓
当前改动代码审查
        ↓
阻塞问题的最小修复
        ↓
许可证与贡献/安全文档
        ↓
README 和历史基线一致性修订
        ↓
GitHub Actions 质量门禁
        ↓
局部验证 → 完整本地验证 → 发布就绪报告
```

审查必须早于 CI 和文档收尾，避免为存在根本问题的状态建立错误基线。CI 在文档之后落地，以确保工作流命令与最终贡献说明一致。

## 4. 验证策略

- 每个修复先运行直接相关的 Vitest 或 pytest 测试。
- 文档与工作流完成后校验 YAML、Compose 配置、锁文件一致性和敏感文件忽略规则。
- 执行 `pnpm api:contract:check`、`pnpm lint`、`pnpm typecheck`、`pnpm test`、集成测试和 `pnpm build`。
- Docker 与浏览器环境可用时执行默认 `pnpm test:e2e`；不执行 `pnpm test:e2e:deepseek`。
- 对 GitHub Actions 做静态检查和命令级本地复现；在尚未推送前，不声称云端工作流已通过。

## 5. 风险与控制

| 风险 | 影响 | 控制方式 |
|---|---|---|
| 当前未提交改动规模大 | 容易遗漏跨模块回归 | 按领域审查差异，先跑既有门禁，再做发布文件 |
| Windows 与 Linux 命令差异 | CI 可能与本地行为不一致 | Windows 复用根命令，Linux 仅直接执行基础设施集成命令 |
| ClamAV 初始化较慢 | CI 超时或不稳定 | 使用 Compose 健康检查，设置合理 Job 超时并保留服务日志 |
| 历史基线含过时设计 | 新贡献者误以为需要登录/多租户 | 明确标注决策已更新并链接最新规格 |
| 无内置认证 | 误暴露公网导致数据风险 | README 与 SECURITY 双重警示反向代理访问控制 |
| 许可证或文档误写 | 开源授权含义不清 | 使用 Apache 官方标准文本，不自行增删条款 |

## 6. 交付与 Git 边界

实施完成后提供修改清单、审查结论、测试结果和已知限制。除非用户再次明确要求，否则不执行 `commit`、`push`、创建仓库、Release 或公开部署。若后续提交，提交标题继续使用简短中文结果描述。

## 7. 计划完成标准

- 实施任务能够按依赖顺序拆成单次可验证的小任务。
- 每项规格验收标准均有对应实施步骤和验证方式。
- CI、文档、审查和安全检查的边界明确。
- 不存在需要在编码中临时决定的架构或法律事项。
