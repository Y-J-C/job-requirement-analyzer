# 开源发布前收尾规格

## 1. 目标

将当前仓库整理到适合提交至 GitHub、供他人在本地部署和验证的状态。重点是补齐开源项目元数据、自动化质量门禁、文档一致性和发布前审查。本阶段不实际发布、推送或部署。

## 2. 范围

### 包含

- 审查当前未提交改动，修复会影响正确性、安全性或开源使用的明确问题。
- 统一 `README.md`、历史需求文档与当前“无内置登录、单实例共享数据集”的实际架构。
- 增加开源许可证、贡献指南和安全问题报告说明。
- 增加 GitHub Actions，在干净环境中执行静态检查、单元测试、构建和必要的基础设施集成测试。
- 检查仓库中是否误包含密钥、上传文件、数据库数据或本地环境配置。
- 运行本地完整验证，并记录未执行项、跳过项与已知限制。

### 不包含

- 不执行 `commit`、`push`、创建 GitHub 仓库或公开发布。
- 不调用真实 DeepSeek API，不把任何密钥写入代码、日志或 CI。
- 不提升 AI 质量指标，不新增指标拆分/合并或目标岗位编辑等业务功能。
- 不升级核心框架，不调整公开 API、数据库结构或总体架构，除非审查发现阻塞发布的缺陷。

## 3. 实施约束

- 保持现有 pnpm workspace、Next.js、FastAPI、PostgreSQL、MinIO 与 ClamAV 架构。
- CI 优先使用 `windows-latest`，复用仓库现有 PowerShell 脚本，避免为 CI 引入第二套命令体系。
- CI 不依赖外部 AI 服务；涉及模型的测试使用现有桩或确定性评测。
- 文档必须说明：系统无内置身份认证，每个部署实例共享一套数据；公开到互联网前应在反向代理层增加访问控制。
- 只处理本阶段范围内的问题；其他功能缺口写入已知限制或后续路线。

## 4. 预期交付物

- `LICENSE`：许可证文本（待用户选择）。
- `CONTRIBUTING.md`：本地环境、分支、测试、迁移和提交要求。
- `SECURITY.md`：私下报告安全问题的方式与部署安全边界。
- `.github/workflows/ci.yml`：无真实密钥的持续集成工作流。
- 修订后的入口文档与必要的架构说明。
- 发布前代码审查结论和可复现的验证结果。

## 5. 验收标准

1. 新贡献者能仅依据仓库文档完成安装、启动、迁移和测试。
2. GitHub Actions 能在无 DeepSeek 密钥时完成预期检查，且失败能阻止质量门禁通过。
3. 文档、Compose 配置、数据库模型和页面中不再描述已移除的用户登录或数据归属机制。
4. 仓库不追踪 `.env`、API 密钥、上传内容、数据库文件或测试产物。
5. 当前改动经代码审查，不存在已知的阻塞级或高优先级问题。
6. 本地验证结果如实记录；真实 DeepSeek 复测明确标记为非 CI、非本阶段必需项。

## 6. 已知后续项

- AI 质量评测 v2 当前精确率和召回率尚未达到目标阈值。
- 指标拆分/合并交互与目标岗位编辑仍属于后续业务阶段。
- 图片岗位信息识别仍按原路线后续加入。

## 7. 待确认事项

- 开源许可证：建议使用 Apache License 2.0；它在宽松授权之外明确提供专利授权与专利终止条款。若更偏好最简短、最宽松的文本，可选择 MIT License。
