# 开源发布前收尾任务清单

## 阶段 A：发布基线审计

### 任务 1：检查仓库边界与敏感信息

**说明：** 只检查 Git 已追踪内容、历史提交名称匹配、忽略规则和发布产物边界，不读取或输出本地 `.env` 的值。

**验收标准：**

- [ ] 已追踪文件不包含密钥、Token、上传内容、数据库文件或测试产物。
- [ ] `.env`、`.data/`、Playwright 产物及本地虚拟环境均被正确忽略。
- [ ] 发现的问题按严重程度记录；敏感值不出现在终端或报告中。

**验证：** `git ls-files`、`git grep -l`、`git check-ignore`、无补丁的 Git 历史匹配检查。

**依赖：** 无
**可能修改文件：** `.gitignore`（仅在发现缺口时）
**规模：** S

### 任务 2：审查后端与数据边界改动

**说明：** 按 API、服务、模型、迁移与安全边界审查当前差异，重点检查无认证单实例语义、数据完整性、错误协议和迁移可逆性。

**验收标准：**

- [ ] 所有阻塞级和高优先级发现均有文件、位置、影响和复现依据。
- [ ] 确认移除身份归属后不存在残留过滤或跨表不一致。
- [ ] 不把历史迁移中为支持降级而保留的字段定义误判为运行时残留。

**验证：** 定向 pytest、Alembic `current/heads/history` 与迁移前后数据检查。

**依赖：** 任务 1
**可能修改文件：** 无（只读审查）
**规模：** M

### 任务 3：审查解析、AI 与 Worker 改动

**说明：** 检查文件解析、OCR、恶意软件扫描、DeepSeek 适配、质量评测和持久化任务处理的失败路径与资源限制。

**验收标准：**

- [ ] 输入边界、超时、重试、幂等性和错误清理行为均有证据支持。
- [ ] 默认测试不会读取密钥或调用真实模型。
- [ ] 阻塞级和高优先级发现被单独列出。

**验证：** 相关 pytest 单元测试及现有集成测试。

**依赖：** 任务 1
**可能修改文件：** 无（只读审查）
**规模：** M

### 任务 4：审查前端、契约与 E2E 改动

**说明：** 检查页面主流程、API 生成类型、错误处理、无登录界面一致性，以及 E2E 数据隔离和清理行为。

**验收标准：**

- [ ] 前端不再依赖登录状态或发送身份请求头。
- [ ] UI、API 契约和后端响应保持一致。
- [ ] E2E 默认路径确定性运行且不调用真实 DeepSeek。

**验证：** Vitest、API 契约检查和定向 Playwright 测试。

**依赖：** 任务 1
**可能修改文件：** 无（只读审查）
**规模：** M

### 检查点 A

- [ ] 汇总任务 1～4 的发现并排序。
- [ ] 每个必须修复的问题拆成不超过 5 个文件的独立补丁，并先补回归测试。
- [ ] 若没有阻塞级或高优先级发现，明确记录“无需修复”，不制造改动。

## 阶段 B：最小问题修复

### 任务 5：修复发布阻塞问题

**说明：** 仅处理检查点 A 确认的阻塞级或高优先级问题。每个问题遵循“失败测试 → 最小修复 → 回归测试”，不同问题不合并为一个大补丁。

**验收标准：**

- [ ] 每个修复都有可复现的失败证据或回归测试。
- [ ] 单个补丁不超过 5 个文件，且不改变未授权的公开接口或产品行为。
- [ ] 中低优先级建议只记录，不在本任务实施。

**验证：** 每个问题对应的最小测试套件；随后运行受影响模块测试。

**依赖：** 检查点 A
**可能修改文件：** 由审查发现确定，每个补丁最多 5 个文件
**规模：** 条件任务；无高优先级发现时跳过

## 阶段 C：开源项目元数据

### 任务 6：增加许可证与协作说明

**说明：** 添加 Apache-2.0 标准许可证、贡献指南与安全报告说明，不复制业务规格或泄露本地配置。

**验收标准：**

- [ ] `LICENSE` 是完整、未经改写的 Apache License 2.0 标准文本。
- [ ] 贡献指南覆盖安装、测试、迁移、提交和 PR 要求。
- [ ] 安全文档明确无内置认证、可信网络边界和私下报告漏洞的方式。

**验证：** 许可证文本来源核对；文档命令与根 `package.json`、README 对照。

**依赖：** 任务 5 或确认跳过任务 5
**可能修改文件：** `LICENSE`、`CONTRIBUTING.md`、`SECURITY.md`
**规模：** M

### 任务 7：统一入口与历史基线文档

**说明：** 保持 README 为当前事实入口，更新历史产品基线中的已决事项和过时认证/多用户描述，同时保留其最初需求背景。

**验收标准：**

- [ ] 安装、启动、测试、模型配置和安全边界与实际代码一致。
- [ ] 不再把登录、多用户或 AI 供应商选择写成当前未决事项。
- [ ] 已知功能缺口与当前 AI 质量指标如实保留。

**验证：** 文档命令逐项映射到脚本；使用定向文本搜索检查过时陈述。

**依赖：** 任务 6
**可能修改文件：** `README.md`、`README-岗位门槛分析系统.md`
**规模：** S

### 检查点 B

- [ ] 开源元数据完整且互不矛盾。
- [ ] 新贡献者路径可以从 README 顺序执行。
- [ ] 文档没有将未来功能表述为已完成。

## 阶段 D：持续集成

### 任务 8：建立 GitHub Actions 质量门禁

**说明：** 使用官方稳定 Actions 创建 Windows 质量任务和 Ubuntu 基础设施集成任务；默认无密钥、无真实模型调用。

**验收标准：**

- [ ] Pull Request 和默认分支推送会触发工作流，并支持手动触发。
- [ ] Windows Job 执行契约、Lint、类型检查、单元测试和构建。
- [ ] Ubuntu Job 执行迁移、PostgreSQL/MinIO 与 ClamAV 集成测试，失败时保留必要的非敏感日志。

**验证：** YAML 解析、Action 与运行时版本核对、各命令本地等价复现；未推送前不声称云端通过。

**依赖：** 检查点 B
**可能修改文件：** `.github/workflows/ci.yml`
**规模：** S

## 阶段 E：发布就绪验证

### 任务 9：运行完整本地质量门禁

**说明：** 依次运行契约检查、静态检查、类型检查、单元测试、基础设施集成测试、构建和默认浏览器 E2E。

**验收标准：**

- [ ] 每条命令的结果、耗时无须记录，但通过、失败和跳过必须如实记录。
- [ ] 不运行真实 DeepSeek 评测或 `test:e2e:deepseek`。
- [ ] 失败项定位到本次改动、既有问题或环境问题，不通过删除测试规避。

**验证：** `pnpm verify`，必要时拆分运行以定位失败。

**依赖：** 任务 8
**可能修改文件：** 仅在发现本阶段引入的问题时修改对应文件
**规模：** M

### 任务 10：形成发布就绪报告并复审差异

**说明：** 汇总交付物、审查结论、验证证据、已知限制和 Git 边界，再执行一次面向合并的最终代码审查。

**验收标准：**

- [ ] 报告区分已验证、未验证和有意跳过内容。
- [ ] 不存在未处理的阻塞级或高优先级发现。
- [ ] 不执行 commit、push、Release 或部署；后续动作等待用户明确要求。

**验证：** `git status`、`git diff --check`、变更范围核对和最终审查。

**依赖：** 任务 9
**可能修改文件：** `docs/open-source-release-readiness-report.md`
**规模：** S

### 最终检查点

- [ ] 规格中的六项验收标准全部有证据。
- [ ] 本地质量门禁完成，云端 CI 状态明确标为待首次推送验证。
- [ ] 仓库达到可提交状态，但没有未经授权执行任何 Git 写操作。
